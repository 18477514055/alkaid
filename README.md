# 瑶光 Alkaid

**极简内核 + 插件化的个人 AI Agent 平台。**

A minimal-core, plugin-based personal AI agent platform that runs entirely on your own machine.

```
后端 Fastify + node:sqlite   ／   前端 React 19   ／   桌面端 Electron
内核 ~22k 行 TypeScript      ／   前端 ~10k 行    ／   单机运行，数据不出本机
```

当前版本：**0.3.0**

---

## 这是什么

瑶光不是「又一个聊天框」。它想做的是一个**能长期用下去的本地 Agent 工作台**：

- **数据在你机器上** —— 对话、记忆、工具调用记录都在本地 SQLite 里，不经过任何中间服务器；
- **模型只是引擎** —— 换模型、换网关、换供应商，不用重建上下文与工作区；
- **能真的动文件** —— 授权工作区、跑命令、读写代码，权限档位说清楚能做什么；
- **记得住事** —— 项目级长期记忆，但**模型只能提议，不能自己拍板**。

## 0.3.0 更新要点

### 安全（本轮重点）
- **本机令牌鉴权**：所有写操作（POST/PATCH/PUT/DELETE）都需要本机令牌，令牌由服务端启动时随机生成，
  只进内存与受限文件，**不进环境变量、不进命令行参数、不进页面 HTML**。
  - **桌面端**：父子进程私有 IPC 自动配对，双击即用，你不会看到配对页；
  - **浏览器**：第一次打开需要用**一次性配对码**兑换（见下方「首次打开浏览器」）；
  - **脚本/CLI**：带 `x-alkaid-token` 请求头，令牌路径由 `/api/healthz` 的 `trust` 段告知（只给路径，不给内容）。
- **阻塞「本地进程冒充人」**：低完整性沙箱里的命令**再也无法**改会话权限档、注册 MCP 服务器、批准原则提案
  —— 这些以前和"你本人点击"是等价的。
- **数据目录加固**：`secrets.json`（全部 API Key）与 `alkaid.db`（全部会话）降为「仅属主 + Medium NRNW」，
  **受限沙箱进程读不到**（实测 `Get-Content secrets.json` 被系统拒绝）。
- **凭证文件先保护、再落位**：写密钥时先在临时文件上打好安全标签，`rename` 之后落盘的就是受保护的文件 ——
  不存在"文件已经可读、标签还没打上"的窗口。
- **桌面壳**：外链只交给系统浏览器（仅 http/https），主窗口不可被导航到外部页面。

### 体验
- 对话按「**一轮 = 一个正文块**」排版：工具调用与它的输出合成一行，展开是**输入 / 输出**两段，思考单独折叠
- **工具门控**（每个对话一套）：一行一组（勾选 + 个数 + 体积 + 约 token + 最近使用），可批量、可折叠、可存模板
- 输入框在模型输出期间变成**停止键**；框里有内容时仍是发送键 —— 这一下是**插话**（排进本轮下一个步骤）
- 子代理可以**只读所有东西**，但**只能改自己的看板**

## 功能

### 对话与模型
- 任何 **OpenAI 兼容端点**都能接（官方 API、自建网关、本地推理服务）
- 每个连接可设**模型白名单**；选择器支持**搜索**与**按提供商分类**
- 上下文窗口档位（32k / 64k / 128k / 200k / 500k / 1M）与**思考强度**逐会话可调
- 模型输出中可**停止**，也可**插话**（不新开一轮，插进当前轮的下一个步骤）

### 工作区与项目
- 工作区 = 你**显式授权**给 Agent 的目录；桌面端可以直接拉起系统目录选择器
- 项目有自己的共享目录与**独立记忆**；删项目只解绑对话，**不会连对话一起删**
- 对话有「当前目标 / 有序任务 / 动态」的执行看板，右侧栏与委派看板都按 Markdown 渲染

### 工具系统
- **内置工具**、**MCP 服务器**、**插件工具**三类统一管理
- 每个工具三态：**常驻 / 按需 / 关闭**；支持按**来源分组**批量设置与折叠；分组归属由服务端按注册表反查（不猜名字）
- 权限档位：`readonly` / `workspace` / `project` / `workspace_project` / `full`
  —— **可见性也是权限**：看不到的工具不会出现在模型的工具表里

### 项目记忆
- 模型**只能提交提案**；正式记录由人工或维护 AI **独立审批**后才写入
- **原则类记录永不由 AI 批准、修改或删除**
- 可选「对话结束后自动批准不冲突的提案」—— 只批准**本对话自己写的**、不冲突的、非原则的；
  别人的留给维护 AI 的多作者合并
- 暂存区的文本，**来源对话自己可以改**（不必走审批），但改不了性质与目标版本
- 记忆 100% 本地、按项目隔离，不写进工作区文件、不上云

### 子代理与团队
- 主对话可以派**子代理**（它是一个**真实会话**，可以点进去看完整过程）
- Agent Team 共享任务板协调并行工作；写作用域重叠只是**建议**，不是锁
- 子代理的共享板属于委派树的**根**，不是每个子代理一本账

### 上下文压缩
- 上下文接近窗口上限时自动压缩，也可手动触发
- 摘要**带原文指针**，被压掉的原文永远可以逐字回读
- 压缩不会删除任何消息

## 安全模型与已知边界

**这一节请务必读完再决定把它用在什么场景。**

| 项 | 现状 |
|---|---|
| 令牌证明什么 | **持有凭证**，不是"硬件级真人证明"。拿到令牌的人/进程等于拿到了你的界面权限 |
| 本机令牌挡住谁 | 受限的**低完整性**进程（`pwsh` 沙箱）、**其他本地用户**、局域网里没有 Origin 的写请求 |
| 本机令牌**挡不住**谁 | **同一用户**的普通（Medium/full）进程 —— 它本就能读你的所有文件，令牌对它只是多一层形式 |
| 数据目录 | `secrets.json` / `alkaid.db` 已降为「仅属主 + Medium NRNW」⇒ **受限沙箱读不到**；但同用户普通进程仍可读（**DPAPI 加密尚未实现**） |
| 应用目录之外的用户文件 | 依然可被低完整性沙箱**读取**（写不行）。彻底治理需要 AppContainer，尚未实现 |
| 沙箱能做什么 | 受限档下命令**只能写**自己的沙箱目录；读不受限（Windows MIC 默认只挡写） |
| 密钥存储 | 明文存放在数据目录，靠 NTFS ACL + 完整性标签保护；**未做磁盘加密** |

如果你需要抵抗"同一用户下的恶意程序"，唯一可靠的做法是把它跑在单独的 Windows 账户或虚拟机里。

## 快速开始

```bash
git clone https://github.com/18477514055/alkaid.git
cd alkaid
pnpm install

# 构建前端产物
pnpm web:build

# 启动（后端 + 网页界面）
pnpm start
```

终端会打印地址（默认 `http://127.0.0.1:8787`）。

### 首次打开浏览器：需要配对码

出于安全，**普通浏览器第一次访问**会用一次性配对码兑换登录 Cookie（10 分钟内有效、只能用一次）：

1. 打开页面，会看到配对提示；
2. 终端里的启动日志会给出**配对码文件路径**，也可以在 `http://127.0.0.1:8787/api/healthz` 的 `trust.pairingPath` 看到路径；
3. 读取该文件内容（一行字符串），粘进页面即可。

```powershell
# Windows PowerShell 示例
Get-Content "<healthz 里 trust.pairingPath 给出的路径>"
```

配对成功后浏览器会拿到一个 **HttpOnly** Cookie（页面脚本读不到它），刷新即保持登录。
若需要换一台设备或另一个浏览器：**重启应用**会生成新的配对码。

> 用 **桌面端** 则不需要这一步 —— 父子进程会通过私有 IPC 自动配对。

### 配置模型

在 **设置 → 连接** 里添加你的模型端点：

- **Base URL**：如 `https://api.deepseek.com/v1`
- **API Key**：只保存在本机密钥文件里，界面不会回显
- **模型**：可拉取列表或手填；每个连接可以勾选**允许使用哪些模型**

## 开发

```bash
pnpm dev          # 内核热重载
pnpm web:dev      # 前端开发服务器
pnpm typecheck    # 双 tsconfig 类型检查
pnpm test         # 全量测试（node --test）
pnpm gate         # 门禁：类型检查 → 全量测试 → 前端构建 → 4 个隔离 HTTP 夹具
```

`pnpm gate` 是提交前的唯一门槛，它跑的是**真实 HTTP 夹具**，不是只跑单元测试。

### 目录结构

```
src/          内核：Fastify 路由、Agent 循环、工具、记忆、压缩、沙箱
web/          前端：React 19 + 自绘样式
desktop/      Electron 外壳（主进程 + preload）
scripts/      门禁、打包、各类验收脚本
test/         单元 + e2e
plugins/      插件示例与宿主边界
assets/       图标等静态资源
```

### 数据在哪

默认 `~/.alkaid`（可用 `ALKAID_HOME` 覆盖）：

| 路径 | 内容 |
|---|---|
| `alkaid.db` | 对话、消息、记忆、审计（SQLite） |
| `secrets.json` | 各连接的 API Key（**明文**，靠文件权限保护） |
| `local-auth-<随机>/` | 本机令牌与配对码（一次性，启动即换） |
| `plugins/` | 插件目录 |

**备份**：直接复制整个目录即可（应用关闭时做）。
**清空**：删除该目录会丢掉全部对话与记忆 —— 不可恢复。

## 已知边界

- **同用户进程不隔离**：见上表，本机令牌与完整性标签挡不住同一用户下的普通程序；
- **未做磁盘加密**：`secrets.json` 是明文，靠 ACL + 完整性标签；
- **应用目录之外的文件读取不受限**（低完整性沙箱），只挡写；
- **macOS / Linux 未系统验证**：Windows 专属的沙箱与凭证保护在其它平台上会退化为权限位检查；
- **记忆审批需要人**：原则类记录永远需要人工批准，这是设计选择，不是缺陷。
